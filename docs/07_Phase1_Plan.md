# Phase 1 Plan: Base Qt Widgets Framework

状态：已完成

## 1. 目标

把 Phase 0 的占位窗口提升为可维护的基础应用框架，但不进入密码库、文件扫描、7-Zip 密码测试或解压业务。

## 2. 本阶段要做

1. 主窗口结构
   - 左侧导航。
   - 右侧页面容器。
   - 状态栏。
   - 基础窗口尺寸和标题。

2. 设置页基础能力
   - 显示程序目录。
   - 显示 `data/config/logs/backup/tools/7zip` 路径。
   - 检查内置 `tools/7zip/7z.exe` 是否存在。
   - 显示 7-Zip 版本检测结果。

3. 日志基础能力
   - `app.log`
   - `error.log`
   - 日志写入封装。
   - 设置页显示日志目录入口。

4. 应用路径服务
   - 所有运行目录从 exe 所在目录计算。
   - 不依赖当前工作目录。
   - 不依赖系统 PATH 查找 7-Zip。

5. 基础样式
   - 干净、克制的 Qt Widgets 样式。
   - 为后续 iOS / iPadOS 卡片风格预留，但不在本阶段做复杂视觉。

6. 构建脚本
   - 保持 `scripts/check_environment.ps1` 可用。
   - 保持 `scripts/configure_msvc.ps1` 可用。
   - 保持 `scripts/build_msvc.ps1` 可用。

## 3. 本阶段不做

- 不做密码库 CRUD。
- 不做 SQLite 表结构。
- 不做压缩包扫描。
- 不做密码测试。
- 不做解压。
- 不做右键菜单。
- 不做 GPU 加速。
- 不做 QML 页面。
- 不做安装包。

## 4. 涉及模块

| 模块 | 动作 |
| --- | --- |
| `MainWindow` | 从占位页面升级为稳定主框架 |
| `AppPaths` | 补充路径检查和显示所需接口 |
| `AppLogger` | 保持简单日志写入，必要时补错误日志 |
| `SevenZipProbe` | 新增，只负责检测内置 7-Zip 是否存在和版本 |
| `SettingsPage` | 新增，显示路径和 7-Zip 状态 |

## 5. 验收标准

- CMake 配置成功。
- Ninja 编译成功。
- 程序能启动和关闭。
- 首页、密码库、历史记录、解压队列、设置页可切换。
- 设置页能显示程序路径和运行目录。
- 设置页能显示内置 7-Zip 存在状态。
- 设置页能显示 7-Zip 版本。
- 启动和关闭会写入 `app.log`。
- 缺少 7-Zip 时不会崩溃，而是显示缺失状态。

## 6. 回滚方案

如果 Phase 1 改动失败：

1. 保留 Phase 0 可编译骨架。
2. 回退新增页面类和探测类。
3. 保留环境脚本、CMake 和内置 7-Zip。
