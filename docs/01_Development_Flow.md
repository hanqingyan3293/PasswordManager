# PasswordManager Development Flow

版本：v0.1
状态：开发流程草案

## 1. 项目目标

PasswordManager 是一个 Windows 本地离线压缩包密码管理与智能解压辅助工具。第一目标不是破解密码，而是管理用户长期积累的已知密码，并通过历史关联、分类、收藏、说明文件规则解析等方式提高测试和解压效率。

## 2. 总体开发原则

1. 先做正确，再做快。
2. 先做可运行闭环，再做高级体验。
3. 先做本地离线，再讨论扩展能力。
4. 先保证不破坏用户文件，再谈自动化。
5. 每个阶段都必须有明确验收，不一次生成全部代码。

## 3. 阶段路线

### Phase 0：项目初始化

目标：
- 初始化 Git 仓库。
- 建立 CMake + Qt 项目骨架。
- 建立目录结构和基础文档。
- 准备内置 7-Zip 目录。

交付：
- `CMakeLists.txt`
- `src/`
- `include/`
- `resources/`
- `tools/7zip/`
- `data/`
- `config/`
- `logs/`
- `backup/`
- `docs/`

验收：
- 项目可以被 CMake 配置。
- Git 工作区干净。
- README 能说明如何准备环境和启动项目。

### Phase 1：基础 Qt Widgets 框架

目标：
- 做出能启动的 Windows 桌面程序。
- 建立主窗口、导航栏、基础页面容器。
- 建立应用配置、日志、路径管理。

页面：
- 首页
- 密码库
- 历史记录
- 解压队列
- 设置

验收：
- 程序能启动和关闭。
- 页面能切换。
- 日志文件能写入。
- 程序只使用相对目录，不依赖系统安装路径。

### Phase 2：SQLite 与密码库

目标：
- 建立 SQLite 数据库。
- 实现密码新增、编辑、删除、搜索、分类、收藏。
- 保存成功次数、失败次数、备注和来源。

验收：
- 密码记录可增删改查。
- 重启程序后数据仍在。
- 数据库结构版本可识别。
- 支持 JSON 导入导出草案。

### Phase 3：文件扫描

目标：
- 支持单文件、多文件、文件夹递归扫描。
- 识别 ZIP、RAR、7Z。
- 记录文件名、大小、修改时间、快速 Hash。

验收：
- 能把压缩包加入列表。
- 非支持格式被明确跳过。
- 扫描失败有日志，不导致程序崩溃。

### Phase 4：内置 7-Zip 集成

目标：
- 固定调用 `tools/7zip/7z.exe`。
- 实现压缩包密码测试。
- 解析成功、失败、损坏、超时、未支持格式等结果。

验收：
- 不依赖系统 PATH。
- 缺少 `7z.exe` 时给出明确错误。
- 至少支持 ZIP、RAR、7Z 的测试流程。
- 测试不会修改原始压缩包。

### Phase 5：任务系统

目标：
- 建立 WAITING、RUNNING、PAUSED、COMPLETED、FAILED 状态。
- 支持暂停、继续、取消、超时。
- 支持有限多线程任务执行。

验收：
- 多任务不会卡死 UI。
- 任务状态可恢复显示。
- 取消后不会留下异常进程。

### Phase 6：智能匹配

目标：
- 实现密码优先级策略。
- 保存压缩包与成功密码关联。
- 支持分类密码、收藏密码、同目录或同资源组密码。

验收：
- 精确历史成功密码永远最高优先级。
- 匹配顺序可解释、可记录。
- 失败次数会降低普通候选优先级，但不能覆盖成功历史。

### Phase 7：基础解压

目标：
- 密码测试成功后等待用户确认。
- 支持解压队列、暂停、继续、取消、日志。

验收：
- 不自动批量解压。
- 用户可选择输出目录。
- 解压失败可诊断。

### Phase 8：Windows 右键菜单

目标：
- 支持资源管理器右键菜单安装和卸载。
- 支持总开关与单功能开关。

验收：
- 菜单可安装、卸载、恢复。
- 注册表操作有确认和日志。
- 失败时不影响主程序使用。

### Phase 9：UI 优化

目标：
- 引入 iOS / iPadOS 风格卡片化设计。
- 支持深色模式。
- 评估是否引入 QML 页面。

验收：
- 高信息密度但不拥挤。
- 表格、任务队列、设置页易用。
- 深色模式可切换或跟随系统。

### Phase 10：发布测试

目标：
- 生成绿色便携发布包。
- 包含内置 7-Zip、默认配置、数据库初始化逻辑。

验收：
- 新机器解压即可运行。
- 不需要系统安装 7-Zip。
- 用户数据在指定目录内。

### Phase 11：性能与 GPU / 多线程加速专题

目标：
- 评估多线程扫描、Hash 计算、7-Zip 任务并发和 UI 响应。
- 讨论 GPU 是否适合本项目。

初步判断：
- 多线程对扫描、Hash、任务队列有明确价值。
- GPU 对 7-Zip 密码测试未必直接有效，因为真正测试逻辑通常在 7-Zip 内部。
- 如果后期做自定义 Hash、规则生成或密码候选排序，GPU 才可能有讨论价值。

验收：
- 先有性能基线，再决定是否加速。
- 不能为了加速牺牲数据安全、稳定性和可维护性。

## 4. 每阶段固定工作流

1. 读取当前文档和代码。
2. 写本阶段实施计划。
3. 用户确认。
4. 编码。
5. 本地构建。
6. 基础测试。
7. 更新文档。
8. 提交变更说明。
