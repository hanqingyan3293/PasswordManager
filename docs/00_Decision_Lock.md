# PasswordManager Decision Lock

版本：v0.1
状态：开发前锁定草案

## 1. 当前已锁定决策

| 决策项 | 当前选择 | 原因 | 状态 |
| --- | --- | --- | --- |
| 当前 UI 路线 | 纯 Qt Widgets 轻量路线 | QML 试点已验证可行，但会引入 Qt Quick/QML 运行依赖，增加发布包体积和运行时占用；当前优先保持轻量、稳定、便携 | 已确认 |
| 后续 UI 优化方向 | Qt Widgets 现代化 | 继续用 Widgets 做卡片化、高信息密度、表格体验和设置页优化；如需首页概览面板，优先用 Widgets 实现 | 已确认 |
| QML 策略 | 暂不进入当前发布路线 | 只作为后期专题重新评估，不作为默认最终方向；除非收益明显大于体积和占用成本，否则不重新引入 | 已确认 |
| 目标平台 | Windows 本地桌面 | 项目定位是 Windows 离线压缩包密码管理工具 | 已确认 |
| 运行模式 | 绿色便携 | 用户数据、配置、日志和工具依赖都放在项目目录或程序目录下 | 已确认 |
| 体积与占用策略 | 持续压缩发布包体积和运行时占用 | 保留功能前提下，优先减少不必要 Qt 模块、运行时 DLL、重复资源和启动开销 | 已确认 |
| 网络策略 | 不联网 | 不上传、不同步、不使用云服务、不使用 AI | 已确认 |
| 账号系统 | 不做 | 本地单机工具，不引入登录、注册、同步和权限复杂度 | 已确认 |
| 数据库 | SQLite | 适合本地、轻量、可备份、可迁移的数据存储 | 已确认 |
| SQLite 接入 | 优先使用 QtSql | 第一阶段减少第三方封装依赖，利于稳定推进 | 已确认 |
| 7-Zip 策略 | 从第一阶段开始内置在项目目录 | 不依赖系统 PATH，不要求用户单独安装 7-Zip，便于绿色便携发布 | 已确认 |
| 7-Zip 调用方式 | 使用程序相对路径调用内置 7z.exe | 保证行为可控，避免调用到用户电脑上的其他版本 | 已确认 |
| 自动批量解压 | 不做 | 规格书明确禁止；成功测试后必须等待用户确认 | 已确认 |
| 原始文件修改 | 不做 | 只读取、测试、解压到目标目录，不改动用户原始压缩包 | 已确认 |
| GPU / 多线程加速 | 后期专题讨论 | 先保证正确性、可恢复任务和 7-Zip 集成；后期再评估 GPU 是否真正适用 | 已登记 |
| 密码库安全策略 | 明文 SQLite，不加密 | 用户明确确认；开发简单、便于调试，但数据库文件泄露即密码泄露 | 已确认 |

## 2. 防跑偏规则

1. 每个阶段只能实现本阶段范围内的功能。
2. 每个阶段开始前必须写清楚目标、涉及模块、禁止改动、验收标准。
3. 每个阶段结束后必须能运行、能回滚、能说明已完成和未完成内容。
4. 未经确认，不把 P2/P3 功能提前塞进 MVP。
5. 任何新需求都先登记到 `docs/05_Change_Log.md`，再判断是否影响当前阶段。
6. 涉及密码、安全、文件删除、注册表、批量解压的改动必须单独确认。

| 项目 | 需要后续确认的问题 | 建议默认值 |

| 编译器 | Visual Studio 版本 | Visual Studio 2022 Community |
